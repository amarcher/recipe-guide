The bet

From recipe-on-a-screen to a household kitchen.

The arc has four steps. We've shipped the first two. The next two are what makes the app worth living inside.

i.

Execution

One recipe, one screen. Mise, timeline, timers. Andrew's sanctuary. Stays untouched.

ii.

Planner

Sunday-to-Sunday menu. Intake, skeleton, candidates, grocery. Built and live.

iii.

Household

Kids, pantry, Tonight surface, shared mise. The week stops resetting on Sunday.

iv.

Network

Hosted menus, cross-family shelves, delegate-shop. The cookbook becomes social.

Each phase compounds the previous one. The execution layer never moves.

Why this fails

The eye picks food on appetite. The current tile asks you to read four cards in parallel and reason. By candidate three you've forgotten candidate one.

Sprites are too small to hold the dish. The rationale is exactly the kind of text that sounds useful and is instantly skimmed past.

The fix is on the next slide.

What changed

A still-life vignette of hero ingredients on a warm wash — the same algorithm that powers RolodexTile, promoted to a first-class compositional language.

Phasing

Three releases. Each one earns the next.

PHASE I

Make planning feel alive

~ 2 weeks
  • PlanEvent log + canonical-card audit
  • Profile + ProfilePreference (eaters as rows)
  • PantryItem + grocery write-back
  • publishCandidate(scope) refactor
  • MoodTag auto-tagging
  • <MealFace /> primitive · candidate redesign
  • Tonight surface (/plan/[id]/tonight)
  • Mode chooser at plan creation
  • Grocery → mise cascade (no SSE)
"The planner remembers my kids, my pantry stops resetting, candidates have faces, and Tonight tells me what to cook in one screen."
PHASE II

Connect the household

~ 3–4 weeks
  • FamilyEvent channel + SSE / LISTEN-NOTIFY
  • Meezing presence + shared mise
  • MealOutcome capture · profiles learn
  • Mid-week Skip / Leftovers / Swap
  • Promoted-plan Hosted Menu + OG
  • Sprite-driven grocery list
  • Delegate grocery share
  • Public recipe share token
  • Notification inbox (no comments)
"Alicia's grocery purchases pre-check my mise. The kids' thumbs train the planner. Saturday dinner has a publishable menu my mother-in-law screenshots."
PHASE III

Compound the network

~ ongoing
  • Cross-family RecipeShelf
  • Vendor-agnostic grocery deep-link
  • Real Instacart/Walmart integrations
  • Smart auto-reorder (after 3 mo data)
  • Friends graph (only on contact-import)
  • Step-claim "on deck" handoff
  • Library Rolodex carousel
"The more we use it, the more it learns. The more we share, the more it grows."
What we are not building

The cuts list, with reasons.

"Just the gist" Alicia render mode Tonight is Alicia's home. Adding a render flag invites drift.
Voice-driven intake / hands-free cook Alicia plans with wine, not voice. TTS is fragile.
Real-time collaborative intake chat Ninety-second flow doesn't earn presence machinery.
Smart auto-substitution in the editor Insufficient evidence anyone edits pre-cook.
Multi-week / template plans Violates the one-grocery-trip-per-week invariant.
Calendar grid view Settled. The week is a menu, not a calendar.
Friends graph + activity feed No contact-import path. Network can't start.
RecipeComment threads Slack-for-cooking is a graveyard.
Profile editor UI in Phase 1 Accumulate first; build editor on user complaint.
Step-claim "on deck" Two adults in one kitchen just talk.
Settled · 2026-04-28

Four decisions, resolved.

i.

Post-cook share chip on the SaveBar

Approved. Slots into the SaveBar after the photo prompt — additive, does not modify CookCardView. Phase 2 hosting builds on the carve-out.

approved
ii.

Hosted Menu visibility

Public-by-token. /menu/[slug] is anyone-with-URL; no auth wall. Slug is generated only on explicit publish; revocation invalidates it.

public-by-token
iii.

Grocery automation partner

AmazonFresh is the Phase 3 default. Vendor-agnostic deep-link (3.1) ships first as universal fallback; partner integration (3.2) targets AmazonFresh.

AmazonFresh+ deep-link fallback
iv.

Family privacy stance

Unchanged. No per-user privacy within a family. Kid Profile data and MealOutcome are family-readable; MiseCheck stays per-user only as in-flight execution detail.

no per-user privacy

New direction added: sprite generation pivots to OpenAI gpt-image-1 with transparent backgrounds — ships as item 1.13, before <MealFace />.
